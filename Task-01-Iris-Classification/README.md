## Quick Start

```bash

source .venv/bin/activate  # On Windows: .venv\Scripts\activate

pip install -r requirements.txt
```

Run the data sanity check first (works from any directory):

```bash
python src/check_data.py
```

### Run the notebook interactively

The notebook uses paths relative to `notebooks/`, so start Jupyter from there:

```bash
cd notebooks
jupyter notebook 01_iris_exploration.ipynb
```

### Run the notebook headless

```bash
cd notebooks
jupyter nbconvert --to notebook --execute --inplace 01_iris_exploration.ipynb
```

Either way the notebook regenerates every artifact it needs: the three figures
in `reports/figures/` and the three `.pkl` files in `models/`.

## Task Requirements

1. Load the benchmark dataset using Pandas
2. Perform exploratory pairplots with Seaborn
3. Normalize features using StandardScaler()
4. Train LogisticRegression and DecisionTreeClassifier
5. Plot the confusion matrix heatmap and plot the decision boundary visualization

## Results

Both models were trained on the same stratified 80/20 split
(`random_state=42`, 119 training / 30 test rows). The raw CSV contains one
duplicated row (`5.8 / 2.7 / 5.1 / 1.9`, virginica, at indices 101 and 142);
the notebook removes it before splitting.

| Model               | Accuracy | Precision (macro) | Recall (macro) | F1 (macro) |
| ------------------- | -------- | ----------------- | -------------- | ---------- |
| Logistic Regression | 0.9333   | 0.9333            | 0.9333         | 0.9333     |
| Decision Tree       | 0.9333   | 0.9333            | 0.9333         | 0.9333     |

The two models are **tied on every headline metric**, so neither is the better
model on this split. Logistic Regression appears first in the comparison table
only because `idxmax()` returns the first row when values are equal.

All 10 setosa test samples are classified correctly; each model misses exactly

## Using the Saved Models

`models/logistic_regression.pkl` expects **scaled** features, so load
`models/scaler.pkl` first. `models/decision_tree.pkl` expects raw features.
Both models record their feature names, so pass a DataFrame with the original
column names to get a clear error on mismatched input rather than silent
mis-scoring.

```python
import joblib
import pandas as pd

scaler = joblib.load("models/scaler.pkl")
logistic = joblib.load("models/logistic_regression.pkl")
tree = joblib.load("models/decision_tree.pkl")

# columns: sepal_length, sepal_width, petal_length, petal_width
X_new = pd.read_csv("new_samples.csv")

lr_predictions = logistic.predict(scaler.transform(X_new))
dt_predictions = tree.predict(X_new)
```

## Tests

The suite uses the standard library's `unittest`, so it needs no extra
dependencies beyond `requirements.txt`:

```bash
python -m unittest discover -s tests -v
```

What it covers:

- `test_data.py` - schema, row count, class balance, dtypes, duplicate count
- `test_pipeline.py` - rebuilds the split and both models, asserts the published
  accuracy, confusion matrices and stratification
- `test_artifacts.py` - saved models load, record their feature names, and
  reproduce the benchmark; figures exist and are valid PNGs
- `test_notebook.py` - the deliverable is valid nbformat and contains every
  required step plus the artifact-saving calls

## Reproducibility

- All randomness is seeded (`random_state=42`), so re-running the notebook
  reproduces these numbers exactly.
- `requirements.txt` is a full `pip freeze` of the virtual environment, so the
  exact versions are pinned.
- The notebook writes its own figures and models; deleting `reports/figures/`
  and `models/` and re-running it restores them.
